<ComponentPreview name="questionnaire-demo" class="min-h-[35rem]" />

`<tec-questionnaire>` asks a short, ordered set of questions one at a time, with progress, back, skip and submit around them, and gathers the answers once, on submit.

## Usage

```ts
import "@tecton/wc/questionnaire"
```

```html
<tec-questionnaire>
  <tec-questionnaire-progress></tec-questionnaire-progress>
  <tec-questionnaire-item name="direction" required>
    <tec-questionnaire-title>What should we prototype next?</tec-questionnaire-title>
    <tec-questionnaire-description>Choose a direction or write your own.</tec-questionnaire-description>
    <tec-questionnaire-choices>
      <tec-questionnaire-choice value="delegation">
        <span class="font-medium">Delegation</span>
        <tec-questionnaire-choice-description>Show how work moves to a specialist.</tec-questionnaire-choice-description>
      </tec-questionnaire-choice>
      <tec-questionnaire-choice value="both">Both together</tec-questionnaire-choice>
      <tec-questionnaire-input aria-label="Another answer" placeholder="Type another answer…"></tec-questionnaire-input>
    </tec-questionnaire-choices>
    <tec-questionnaire-error></tec-questionnaire-error>
  </tec-questionnaire-item>
  <tec-questionnaire-item name="detail">…</tec-questionnaire-item>
  <tec-questionnaire-actions>
    <tec-questionnaire-previous></tec-questionnaire-previous>
    <tec-questionnaire-skip></tec-questionnaire-skip>
    <tec-questionnaire-next></tec-questionnaire-next>
    <tec-questionnaire-submit></tec-questionnaire-submit>
  </tec-questionnaire-actions>
</tec-questionnaire>
```

```ts
questionnaire.addEventListener("tec-submit", (event) => {
  const answers = event.detail.formData // answers.get("direction"), answers.getAll(…) for multiple items
})
```

## Composition

```text
tec-questionnaire
├── tec-questionnaire-progress
├── tec-questionnaire-item
│   ├── tec-questionnaire-title
│   ├── tec-questionnaire-description
│   ├── tec-questionnaire-choices
│   │   ├── tec-questionnaire-choice
│   │   └── tec-questionnaire-input
│   └── tec-questionnaire-error
└── tec-questionnaire-actions
    ├── tec-questionnaire-previous
    ├── tec-questionnaire-skip
    ├── tec-questionnaire-next
    └── tec-questionnaire-submit
```

The questionnaire owns the ordered items (enabled `tec-questionnaire-item`s in document order), the active item, answer state, validation, progress and navigation. The page, card or dialog around it owns cancellation, persistence and transport.

**Validation**: Next, Enter and Submit need an answer for the active question — or, for an optional one, an explicit Skip. On submit every question is checked and the first invalid one becomes active with its error shown.

**Forms**: the items are form-associated. Inside a `<form>`, the answers are submitted with it under each item's `name` (repeated for `multiple`, nothing for a skipped or disabled item), a form reset restores the initial answers, and `tec-submit` is followed by the form's own submission.

## Explicit Skip

## Shortcuts

`shortcuts="letters"` or `"numbers"` assigns a key to each choice of the active question; the key is shown on the card and exposed as `aria-keyshortcuts`. Shortcuts never act while a text field has focus.

## Custom Validation

## Accessibility

- Each `tec-questionnaire-item` is a group (the fieldset of the question) named by its `tec-questionnaire-title` and described by its descriptions. Only the active item is rendered; the others are hidden.
- Choices are native radio buttons (or checkboxes in a `multiple` item) covering each card, named by the card content; radio answers report their position ("2 of 3") and form one tab stop.
- While invalid, the item and its answers expose `aria-invalid`, and the `tec-questionnaire-error` is an alert that also describes the item. Failed validation focuses the first answer (or the filled text input); successful navigation focuses the new question.
- Progress is a named progress bar ("Question 2 of 3") announced politely; the navigation buttons are real buttons, and the ones that do not apply to the active question are hidden. Next and Submit expose `aria-keyshortcuts="Enter"`, items and choices their own shortcuts.
- Always give `tec-questionnaire-input` an accessible name (`aria-label` or `aria-labelledby`); a placeholder is not a label.

## Usage guidelines

### Use it when

- The assistant asks a short, ordered set of questions before it acts: scope, constraints, review.
- One question is on screen at a time, with progress, back, skip and submit around it, and the answers are gathered once, on submit.

### Not for

- one labelled control with a description and an error, inside a form: use [Field](/docs/components/field)
- a single group of radio options that is part of a larger form: use [Radio Group](/docs/components/radio-group)

### Do

<DoList>

<Do>

Give every `tec-questionnaire-item` a `name`, mark it `required` or `multiple`, and put its answers in `tec-questionnaire-choices`.

</Do>

<Do>

Read the answers from `event.detail.formData` on `tec-submit` — or from the surrounding `<form>`.

</Do>

<Do>

Navigate only with `tec-questionnaire-previous`, `-skip`, `-next` and `-submit` inside `tec-questionnaire-actions`.

</Do>

<Do>

Leave a question out with `disabled` rather than removing it, so the flow, progress and submission stay consistent.

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="A questionnaire hand-built from a radio group">

<Wrong>

```html
<div class="flex flex-col gap-5">
  <h3>What kind of change is this?</h3>
  <tec-radio-group name="change">…</tec-radio-group>
  <tec-button>Submit</tec-button>
</div>
```

</Wrong>

<Correct>

```html
<tec-questionnaire>
  <tec-questionnaire-item name="change" required>
    <tec-questionnaire-title>What kind of change is this?</tec-questionnaire-title>
    <tec-questionnaire-choices>
      <tec-questionnaire-choice value="feature">New feature</tec-questionnaire-choice>
    </tec-questionnaire-choices>
    <tec-questionnaire-error></tec-questionnaire-error>
  </tec-questionnaire-item>
  <tec-questionnaire-actions><tec-questionnaire-submit></tec-questionnaire-submit></tec-questionnaire-actions>
</tec-questionnaire>
```

</Correct>

The hand-built version enforces nothing, has no progress, skip or keyboard flow, and leaves the question unassociated with its answers.

</Dont>

<Dont severity="HIGH" title="A plain submit button in the actions row">

<Wrong>

```html
<tec-questionnaire-actions>
  <tec-questionnaire-next></tec-questionnaire-next>
  <tec-button type="submit">Submit</tec-button>
</tec-questionnaire-actions>
```

</Wrong>

<Correct>

```html
<tec-questionnaire-actions>
  <tec-questionnaire-previous></tec-questionnaire-previous>
  <tec-questionnaire-next></tec-questionnaire-next>
  <tec-questionnaire-submit>Submit brief</tec-questionnaire-submit>
</tec-questionnaire-actions>
```

</Correct>

`tec-questionnaire-submit` appears only on the last question and validates every question first; a plain button is reachable from the first question and submits with later questions unanswered.

</Dont>
