## Usage

```ts
import "@tecton/wc/combobox"
```

```html
<tec-combobox placeholder="Select a framework" aria-label="Framework">
  <tec-combobox-item value="next">Next.js</tec-combobox-item>
  <tec-combobox-item value="svelte">SvelteKit</tec-combobox-item>
  <tec-combobox-item value="astro">Astro</tec-combobox-item>
  <tec-combobox-empty>No items found.</tec-combobox-empty>
</tec-combobox>
```

Typing in the input opens the list and filters it (case- and accent-insensitive `contains`; `filter="starts-with" | "fuzzy" | "none"` or a filter function change it). Choosing an option puts its text in the input and its `value` (its text when it has none) in the element's `value`; `change` fires. Leaving the field with text that matches nothing reverts it to the chosen option, unless `allow-custom-value` is set.

It is a form control: `name`, `required`, `disabled`, `invalid`, form reset and `<fieldset disabled>` work as on a native input.

## Multiple

With `multiple`, chosen options become chips in front of the input and the list stays open while choosing. <Kbd>Backspace</Kbd> in the empty input removes the last chip; <Kbd>←</Kbd> at the start of the input moves to the chips, where <Kbd>Delete</Kbd> removes one. `values` holds the choice; each value is submitted as its own form entry.

## Accessibility

- Follows the WAI-ARIA combobox pattern with a listbox popup, as React Aria's ComboBox: the input is `role="combobox"` with `aria-autocomplete="list"`, `aria-expanded`, `aria-controls` and `aria-activedescendant`. DOM focus never leaves the input; the highlighted option is announced through the active descendant.
- Name it with a [Field](/docs/components/field) label, `<label for>`, `aria-labelledby` or `aria-label` on `tec-combobox`; the listbox takes the same name (or "Suggestions", `list-label`).
- Options are `role="option"` with `aria-selected` and `aria-disabled`; groups are `role="group"` named by their label; separators are decorative. `multiple` sets `aria-multiselectable`.
- The chevron button is hidden from assistive technology (the keyboard does the same); the clear button is named "Clear" (`clear-label`), and chip remove buttons "Remove Apple" (`remove-label`). Chips form a list.
- `invalid` and failed constraints set `aria-invalid` on the input; `required` sets `aria-required` and blocks form submission.

## Usage guidelines

### Use it when

- The list is long enough that typing to narrow it beats scrolling a popup.
- The user picks several values and should see them as removable chips.
- The field still resolves to values from a known collection — or, with `allow-custom-value`, to free text with suggestions.

### Not for

- a short fixed list that needs no typing: use [Select](/docs/components/select)
- a palette that runs commands instead of setting a value: use [Command](/docs/components/command)

### Do

<DoList>

<Do>

Give every `tec-combobox-item` a `value` (or rely on its text); read the choice from `value` / `values` and listen to `change`.

</Do>

<Do>

Name the field: `aria-label` on `tec-combobox`, or a `tec-field-label` when it sits inside a `tec-field`.

</Do>

<Do>

Add a `tec-combobox-empty` so a search without matches says so instead of closing the list.

</Do>

<Do>

Add a `label` to any item whose content is markup, so filtering and the input text have a string.

</Do>

<Do>

For multi-select add `multiple`; the chosen options become chips automatically.

</Do>

<Do>

Open the suggestions on focus when recent picks (the last wells opened) help before typing (`menu-trigger="focus"`).

</Do>

<Do>

Query a server-backed combobox after the user pauses typing, not on every keystroke (debounce `tec-input-change`, then replace the items).

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="A combobox rendered with no accessible name">

<Wrong>

```html
<tec-combobox placeholder="Framework">…</tec-combobox>
```

</Wrong>

<Correct>

```html
<tec-combobox aria-label="Framework" placeholder="Select a framework">…</tec-combobox>
```

</Correct>

A placeholder is not a label: it disappears as soon as the user types, so the control is announced as an unnamed combobox.

</Dont>

<Dont severity="HIGH" title="Reading the typed text as the value">

<Wrong>

```js
combobox.addEventListener("input", () => save(combobox.inputValue))
```

</Wrong>

<Correct>

```js
combobox.addEventListener("change", () => save(combobox.value))
```

</Correct>

`inputValue` is whatever is typed right now ("Nex"); `value` is the chosen option's value ("next") and only changes when the user commits a choice. Listen to `tec-input-change` for the typed text (to fetch suggestions), and to `change` for the value.

</Dont>

<Dont severity="MEDIUM" title="No empty state when the filter matches nothing">

<Wrong>

```html
<tec-combobox aria-label="Framework">
  <tec-combobox-item>Remix</tec-combobox-item>
</tec-combobox>
```

</Wrong>

<Correct>

```html
<tec-combobox aria-label="Framework">
  <tec-combobox-item>Remix</tec-combobox-item>
  <tec-combobox-empty>No items found.</tec-combobox-empty>
</tec-combobox>
```

</Correct>

Without an empty element the popup closes as soon as nothing matches, so the typist sees the list vanish instead of a "no results" message.

</Dont>
